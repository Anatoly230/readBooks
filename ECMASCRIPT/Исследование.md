# 🔷 Глобальная последовательность по спецификации
---
# 1️⃣ Загрузка исходного текста
### 📘 Раздел:
ECMAScript Language: Source Text
Движок получает текст скрипта как последовательность Unicode-символов.
---
# 2️⃣ Лексический анализ (Tokenization)
### 📘 Раздел:
Lexical Grammar
Текст разбивается на:
- Keywords (`var`, `let`, `function`)
    
- Identifiers (`firstStudent`)
    
- StringLiteral
    
- NumericLiteral
    
- Punctuators (`=`, `{`, `}` и т.д.)
    
---
# 3️⃣ Синтаксический анализ (Parsing)
### 📘 Раздел:
ECMAScript Language: Scripts and Modules  
→ ParseScript  
→ Script : ScriptBody
Создаётся AST (Abstract Syntax Tree).
Если есть синтаксическая ошибка — выполнение останавливается здесь.
---
# 4️⃣ ScriptEvaluation
Вот тут начинается реальная магия.
### 📘 Раздел:
**ScriptEvaluation**
Алгоритм:
1. Let script be ParseScript(sourceText).  
2. Let globalEnv be the Global Environment Record.  
3. Perform GlobalDeclarationInstantiation(script, globalEnv).  
4. Evaluate script.
---
# 5️⃣ GlobalDeclarationInstantiation
Это самая важная фаза — создание окружений.
### 📘 Раздел:
GlobalDeclarationInstantiation
Здесь происходит:
---
## 5.1 Создание Environment Records
Создаются:
- Object Environment Record (для `var`)
    
- Declarative Environment Record (для `let`, `const`)
    
---
## 5.2 Обработка Function Declarations
Спецификация говорит:
1. Собрать все `FunctionDeclaration`
    
2. Создать функции
    
3. Положить их в Environment
    
👉 Поэтому `whatAge` и `greeting` доступны до вызова.
---
## 5.3 Обработка var
var firstStudent
Создаётся binding в ObjectEnvironmentRecord:
firstStudent → undefined
---
## 5.4 Обработка let / const
respect  
temp
Создаются в DeclarativeEnvironmentRecord.
НО!
Они находятся в состоянии:
uninitialized (TDZ)

# 1️⃣ Что реально возвращает ParseScript
Важно понять:
ParseScript НЕ возвращает AST напрямую.
Он возвращает **Script Record**.
Внутри него:
Script Record {  
  [[Realm]]: realm,  
  [[ECMAScriptCode]]: script,  
  [[LoadedModules]]: « »,  
  [[HostDefined]]: hostDefined  
}
И вот ключевое:
👉 `[[ECMAScriptCode]]` — это и есть результат синтаксического анализа  
👉 это parse node типа **Script**

# 2️⃣ Что такое `Script : ScriptBody`
В грамматике спецификации есть правило:
Script :  
    ScriptBody
А ScriptBody — это:
ScriptBody :  
    StatementList
То есть по факту:
Script  
└── ScriptBody  
└── StatementList  
└── список Statement

# 🧠 Большая картина целиком
После `ParseScript` у нас есть:
Script Record {

`[[ECMAScriptCode]]:` `<AST с корнем Script>`,  
`[[LoadedModules]]:` « »,  
`[[HostDefined]]:` hostDefined

ScriptEvaluation(scriptRecord)

# 🔷 Шаг 1 — Создание Global Execution Context
Раздел спецификации:  
**Execution Contexts**
Создаётся структура:
**`Execution Context`** {  
  `LexicalEnvironment`  
  `VariableEnvironment`  
  `Realm`  
  `ScriptOrModule`  
}
И вот здесь важно:
👉 В `ScriptOrModule` кладётся  
`scriptRecord.[[ECMAScriptCode]]`
То есть:
AST не преобразуется.  
Он просто прикрепляется к Execution Context.

---
# 🔷 Шаг 2 — Создание Global Environment Record
Раздел:  
**NewGlobalEnvironment**
Создаются два слоя:
GlobalEnvironmentRecord  
├── ObjectEnvironmentRecord   (для var)  
└── DeclarativeEnvironmentRecord (для let/const)

# 🔷 Шаг 3 — GlobalDeclarationInstantiation
Вот тут AST начинают «читать».
Алгоритм буквально проходит по `ScriptBody.StatementList`.
Он НЕ выполняет код.  
Он делает декларационную фазу.

# 🔥 Что происходит с AST на этом этапе?
Спецификация делает примерно следующее:
```
For each element d of scriptBody:  
    If d is FunctionDeclaration → собрать  
    If d is VariableDeclaration → собрать  
    If d is LexicalDeclaration → собрать
```
Это обход верхнего уровня AST.

# ⚙️ Как AST выполняется
Каждый узел AST имеет в спецификации метод вида:
Runtime Semantics: Evaluation
Например:
### VariableStatement : var VariableDeclarationList ;
имеет алгоритм:
1. For each VariableDeclaration  
2. Evaluate initializer  
3. Call InitializeBinding
---
# 🔬 Пример: выполнение первой строки
AST узел:
VariableStatement
Вызывается:
Evaluate(VariableStatement)
Выполняется:
firstStudent = "Anatoly"

---
# 🧠 Важное понимание
AST НЕ преобразуется в байткод (в рамках спецификации).
Спецификация описывает это так:
Each parse node has associated runtime semantics.
То есть:
AST узел → вызывает свой алгоритм → изменяет Environment → возвращает Completion Record.

---
# 🔥 Completion Record
Каждое выполнение возвращает:
Completion {  
 ` [[Type]]: normal | throw | return | break`  
 ` [[Value]]: значение ` 
 ` [[Target]]: метка`  
}
ScriptEvaluation в конце возвращает Completion Record всего скрипта.

---
# 🧠 Теперь вся картина целиком
Source Text  
   ↓  
ParseScript  
   ↓  
AST (Script node)  
   ↓  
Script Record  
   ↓  
ScriptEvaluation  
   ↓  
Create Global Execution Context  
   ↓  
Create Global Environment  
   ↓  
GlobalDeclarationInstantiation  
   ↓  
Environment заполнен  
   ↓  
Evaluate(AST)  
   ↓  
Completion Record
---
# 🧬 Главное открытие
AST:
- создаётся один раз
- прикрепляется к Execution Context
- используется дважды:
    1. для декларационной фазы
    2. для фазы выполнения
    
---
# 💥 Самое важное для понимания
Execution Context не "строится из AST".
Он создаётся отдельно.
AST просто:
- хранится
- обходится
- вызывает алгоритмы Evaluation
