### 1. Environment Record (запись окружения)

Это **абстрактный тип** (структура данных), который хранит **привязки идентификаторов** — то есть соответствие между именами переменных/функций и их значениями.  
Она создаётся не непосредственно из AST, а в процессе выполнения кода для каждой области видимости (например, для функции, блока, глобального кода). Однако можно сказать, что её структура и набор идентификаторов определяются статическим анализом кода (AST) — какие объявления (`var`, `let`, `const`, `function` и т.д.) присутствуют в данной области.

В спецификации выделяют несколько видов Environment Record:

- **Declarative Environment Record** — для хранения объявлений (переменные, функции и т.д.) в блоках и функциях.
    
- **Object Environment Record** — для случаев, когда привязки хранятся в объекте (например, глобальный объект или `with`).
    
- **Global Environment Record** — комбинация объектной и декларативной записей для глобальной области.
    
- **Module Environment Record** — для модулей.
    

### 2. Lexical Environment (лексическое окружение)

Это **структура**, которая используется механизмом разрешения имён (identifier resolution). Каждое лексическое окружение состоит из:

- **Environment Record** — собственно записи с привязками.
    
- **Ссылки на внешнее лексическое окружение** (`outer`) — для реализации вложенности областей видимости (цепочка областей).
    

### 3. Execution Context (контекст выполнения)

Это абстрактное понятие, которое описывает окружение, в котором выполняется код. У каждого контекста выполнения есть несколько компонентов, среди которых:

- **LexicalEnvironment** — ссылка на лексическое окружение, используемое для разрешения имён в текущем коде (для `let`, `const`, функций, блоков).
    
- **VariableEnvironment** — ссылка на окружение, которое хранит привязки, созданные через `var` и объявления функций (исторически сложилось разделение для совместимости).
    
- **ThisBinding** — значение `this` для данного контекста.
    

Итак, ваша формулировка:

- `environmentRecord` — это запись идентификаторов (в том смысле, что хранит их привязки) — **верно**.
    
- `lexicalEnvironment` — это свойство `executionContext`, содержащее `environmentRecord` и ссылку на внешнее окружение (`outer`) — **верно**.
    

### Дополнительные нюансы

- В спецификации обычно говорят не о прямом хранении `environmentRecord` внутри `lexicalEnvironment`, а о том, что `Lexical Environment` **состоит из** Environment Record и ссылки на внешнее окружение.
    
- В процессе выполнения кода `LexicalEnvironment` может меняться (например, при входе в блок создаётся новое лексическое окружение).
    
- Существует также понятие **VariableEnvironment**, которое похоже, но используется для `var`-объявлений. В большинстве случаев они ссылаются на одно и то же окружение, но в блоках с `let/const` и функциях они могут различаться.

## 1. Виды Environment Record (записей окружения)

Спецификация выделяет несколько типов, каждый со своими особенностями.

- **Declarative Environment Record**  
    Используется для хранения объявлений: переменные (`let`, `const`, `var`), функции, классы, а также параметры функций. Это «классическая» запись, где каждая привязка имеет имя и значение, а также может быть помечена как _immutable_ (неизменяемая) для `const`.
    
- **Object Environment Record**  
    Связывается с объектом, например, с глобальным объектом (в браузере — `window`) или с объектом, переданным в конструкцию `with`. Доступ к идентификаторам в этом случае происходит как к свойствам объекта. Если свойство не найдено, оно может создаваться динамически (как при обращении к необъявленной переменной в глобальной области).
    
- **Global Environment Record**  
    Особый гибрид: он содержит и **object record** (для глобального объекта, куда попадают `var`-объявления и функции верхнего уровня), и **declarative record** (для `let`, `const`, `class` в глобальной области). При поиске сначала просматривается declarative часть, потом object часть.
    
- **Module Environment Record**  
    Разновидность declarative, но с дополнительными правилами для импортов/экспортов и неизменяемостью привязок импорта.
    

## 2. LexicalEnvironment vs VariableEnvironment

В контексте выполнения есть два похожих поля: `LexicalEnvironment` и `VariableEnvironment`. Зачем два?

Исторически в ES3 была только одна среда для переменных. Но с появлением `let` и `const` понадобилось различать привязки, которые видны с момента входа в область (`var` и функции) и привязки, которые видны только после выполнения строки объявления (`let`, `const`, `class`).

- **VariableEnvironment** — окружение для «устаревших» объявлений: `var` и функций (через FunctionDeclaration). Оно создаётся один раз при входе в контекст (например, в функцию) и остаётся неизменным для всего контекста, если только не встречается `eval` или `with` (которые могут его модифицировать).
    
- **LexicalEnvironment** — окружение для «лексических» объявлений: `let`, `const`, `class`, а также для блоков (`{}`). Оно может меняться: при входе в блок создаётся новое лексическое окружение, которое ссылается через `outer` на внешнее.
    

### Пример для понимания:

javascript

function foo() {
  var a = 1;        // попадёт в VariableEnvironment
  let b = 2;        // попадёт в LexicalEnvironment
  if (true) {
    var c = 3;      // всё ещё VariableEnvironment (var не ограничена блоком)
    let d = 4;      // новое лексическое окружение блока
  }
}

При входе в `foo` создаётся контекст выполнения.

- `VariableEnvironment` получает запись с привязками `a` и `c` (да, `c` поднимается на уровень функции, хотя объявлена внутри блока).
    
- `LexicalEnvironment` изначально указывает на ту же запись? Нет — обычно `LexicalEnvironment` в начале выполнения функции тоже указывает на то же окружение, что и `VariableEnvironment`? На самом деле спецификация говорит, что для кода функции инициализация `LexicalEnvironment` и `VariableEnvironment` происходит из одного и того же окружения, но затем при входе в блок создаётся новое лексическое окружение для блока, и оно становится текущим `LexicalEnvironment`. При этом `VariableEnvironment` остаётся неизменным (ссылается на окружение функции).  
    Когда мы входим в `if`, создаётся новое Declarative Environment Record, связанное с блоком, его `outer` указывает на текущее лексическое окружение (которое для функции могло быть либо окружением функции, либо уже изменённым). В это новое окружение попадает `let d`. После выхода из блока `LexicalEnvironment` восстанавливается до предыдущего.
    

Таким образом, `var` и функции привязаны к `VariableEnvironment` и видны во всей функции, а `let/const` живут в `LexicalEnvironment` и подчиняются блочной области видимости.

## 3. Создание Environment Record и фазы выполнения

Когда интерпретатор входит в новую область (функцию, блок, модуль), он:

1. Создаёт новый **Environment Record** нужного типа.
    
2. Определяет `outer` — ссылку на внешнее окружение (обычно это `LexicalEnvironment` текущего контекста на момент создания).
    
3. Создаёт **Lexical Environment**, состоящий из этой записи и ссылки `outer`.
    
4. Если это вход в функцию, также инициализирует **VariableEnvironment** (часто тем же окружением, но это может быть отдельный экземпляр в особых случаях, например, в `with` или `eval`).
    

Далее происходит **фаза связывания (binding instantiation)**:

- Для `var` и функций: создаются привязки в `VariableEnvironment`, причём для `var` начальное значение `undefined`, для функций — сразу тело функции.
    
- Для `let`, `const`, `class`: создаются привязки в `LexicalEnvironment`, но они помечаются как **неинициализированные** (uninitialized). До момента выполнения строки объявления к ним нельзя обращаться — это и есть **Temporal Dead Zone (TDZ)**.
    

## 4. Temporal Dead Zone (TDZ)

TDZ — это промежуток времени от входа в область (где идентификатор уже известен окружению) до момента фактической инициализации переменной значением. В этот период доступ к идентификатору вызывает `ReferenceError`.

Как это реализовано в Environment Record?  
У привязки есть внутренний флаг **initialized**. Для `let` и `const` при создании он установлен в `false`. При выполнении `let x = 5;` флаг становится `true` и присваивается значение. До этого любое обращение к `x` проверяет флаг и выбрасывает ошибку. Для `var` флаг всегда `true`, и значение `undefined` присваивается сразу.

## 5. Разрешение идентификаторов (Identifier Resolution)

Когда в коде встречается имя переменной, движок выполняет алгоритм **GetIdentifierReference(lex, name, strict)**:

1. Если `lex` равно `null`, возвращает `undefined` (глобальный объект не найден — в строгом режиме будет ошибка при присваивании).
    
2. Ищет привязку в `EnvironmentRecord` текущего `LexicalEnvironment`.
    
3. Если находит — возвращает ссылку на эту привязку.
    
4. Если не находит — повторяет шаги с `outer` текущего окружения.
    

Этот механизм обеспечивает лексическую область видимости и замыкания: функция «запоминает» своё внешнее окружение через скрытое свойство `[[Environment]]`, которое копирует значение `LexicalEnvironment` на момент создания функции. При вызове это окружение становится `outer` для нового контекста выполнения.

## 6. Пример с замыканием

javascript

function outer() {
  let x = 10;
  function inner() {
    console.log(x);
  }
  return inner;
}
const fn = outer();
fn(); // 10

Что происходит:

- При вызове `outer` создаётся контекст выполнения. `LexicalEnvironment` содержит запись с `x` (неинициализирована, затем инициализируется) и запись для `inner` (инициализирована функцией).
    
- У функции `inner` при её создании внутреннее свойство `[[Environment]]` устанавливается в текущий `LexicalEnvironment` (окружение `outer`).
    
- После завершения `outer` её контекст разрушается, но окружение остаётся в памяти, потому что на него ссылается `[[Environment]]` функции `inner`.
    
- При вызове `fn()` создаётся новый контекст для `inner`, его `outer` берётся из `[[Environment]]`, и разрешение `x` идёт по цепочке до окружения `outer`.
    

## 7. Особенности глобального окружения

Глобальный контекст имеет `LexicalEnvironment` и `VariableEnvironment`, которые оба ссылаются на **Global Environment Record**. В этом Record:

- Есть объектная запись (object record) для глобального объекта (например, `window`). Туда попадают `var`-переменные и функции верхнего уровня.
    
- Есть декларативная запись (declarative record) для `let`, `const`, `class` верхнего уровня. Они не становятся свойствами глобального объекта, но при этом видны везде.
    

Поэтому:

javascript

var a = 1;
let b = 2;
console.log(window.a); // 1
console.log(window.b); // undefined

## Заключение

Таким образом, Environment Record — это непосредственное хранилище привязок, а LexicalEnvironment — это обёртка, добавляющая ссылку на внешнее окружение. Контекст выполнения оперирует двумя такими обёртками (LexicalEnvironment и VariableEnvironment) для разделения разных типов объявлений. Это позволяет реализовать блочную область видимости, TDZ, замыкания и другие важные механизмы языка.
