---
## 🔹 1. «Она же уже написана — зачем её создавать?»
Когда ты пишешь:
`function greeting(n) { ... }`
в исходном тексте — это **не функция**.
Это:
`Parse Node` (`AST` узел типа `FunctionDeclaration`)
То есть это просто структура данных, описывающая синтаксис.

Она не:
- не объект
- не callable
- не имеет `[[Environment]]`
- не имеет `[[Call]]`
- не имеет `prototype`

Это просто узел дерева.

---
### 🔥 Что значит «создать function object»

Во время `GlobalDeclarationInstantiation` вызывается алгоритм:
`InstantiateFunctionObject`
(внутри используется `OrdinaryFunctionCreate`)
Вот тогда создаётся настоящий объект функции.
Он выглядит концептуально так:

FunctionObject {  
  `[[Call]]:` internal call algorithm  
  `[[Environment]]:` ссылка на окружение  
  `[[ECMAScriptCode]]:` ссылка на FunctionBody (AST узел)  
 ` [[FormalParameters]]`  
  `[[Realm]]`  
  prototype: { constructor: ... }  
}
Вот теперь это объект.
Теперь его можно:
- положить в переменную
- передать как аргумент
- вызвать

---
### 🔹 Важно понять разницу
| Что                                 | Это что        |
| ----------------------------------- | -------------- |
| `function greeting(n) {…} в тексте` | AST узел       |
| Function Object                     | Runtime объект |

---
### 🔥 Ключевой момент
Когда спецификация говорит:
 "Создать function object"
Она имеет в виду:
Создать **runtime-объект**, который ссылается на AST функции.

То есть:
AST остаётся один.  
`Function Object` — это оболочка вокруг AST + окружение.

---
# 🔹 2. Что происходит при вызове функции?
Теперь твой второй вопрос:

 создаётся ли новая функция при вызове?
Ответ:
❌ Нет.  
`Function object` НЕ создаётся заново.
Создаётся:
Новый Execution Context

---
# 🔬 Что реально происходит при вызове
Когда ты вызываешь:
`greeting("Anatoly")`
Спецификация делает:

`Call(functionObject, arguments)`
Алгоритм:
1. Создать новый Execution Context
    
2. Создать новый LexicalEnvironment
    
3. Связать параметры
    
4. Выполнить [[ECMAScriptCode]] функции
    
---
# 🔥 Важное
Function Object:
- один
    
- создан в декларационной фазе
    
- лежит в environment
    
Execution Context:
- создаётся каждый вызов
    
- уничтожается после завершения
    
---
# 🧠 Визуально
После загрузки скрипта:
AST (Script)  
   └── FunctionDeclaration (greeting)  
  
↓ GlobalDeclarationInstantiation  
  
FunctionObject #1  
   [[ECMAScriptCode]] → ссылка на AST узел FunctionBody  
   [[Environment]] → globalEnv
---
При вызове:
Call(FunctionObject #1)  
  
↓ создаётся  
  
ExecutionContext #1  
   LexicalEnvironment  
   VariableEnvironment  
   Outer → FunctionObject.[[Environment]]
---
# 🔥 А вот теперь интересное
Если функция возвращает функцию:
return function nice(c) { ... }
Вот тут:
✔️ создаётся новый function object  
✔️ при каждом вызове greeting
Почему?
Потому что это **FunctionExpression**, а не FunctionDeclaration.
---
# 🔬 Разница:
|Тип|Когда создаётся function object|
|---|---|
|FunctionDeclaration|во время GlobalDeclarationInstantiation|
|FunctionExpression|во время выполнения строки|
---
# 🔥 В твоём коде
function greeting(n) {  
  return function nice(c) { ... }  
}
- greeting → создаётся один раз
    
- nice → создаётся КАЖДЫЙ вызов greeting
    
---
# 🧠 Самое главное понимание
Есть три сущности:
1. AST (синтаксис)
    
2. Function Object (runtime объект)
    
3. Execution Context (вызов)
    
Они НЕ одно и то же.
---
# 💡 Короткий ответ на твои вопросы
> она же у меня написана, зачем её ещё раз создавать?
Потому что написанное — это AST.  
А нужно создать runtime объект.
---
> создаётся ещё одна при вызове?
Function Object — нет.  
Execution Context — да.  
FunctionExpression внутри — да.
