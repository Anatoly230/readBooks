## 1️⃣ InstantiateFunctionObject (поверхностно)

Этот алгоритм делает примерно:

1. Let name be `"greeting" ` 
2. Let sourceText be `исходный текст функции`  
3.  `Let F` = `OrdinaryFunctionCreate(...)`  
4.  `Perform SetFunctionName(F, name)`  
5.  `Return F`

⚠️ Важное: именно здесь берётся текущий `LexicalEnvironment`  
и передаётся в `OrdinaryFunctionCreate` как `env`.

---

## 2️⃣ OrdinaryFunctionCreate(...) — очень подробно

В твой момент вызова передаются:

functionPrototype → %Function.prototype%  
sourceText        → текст greeting  
ParameterList     → (n)  
Body              → FunctionBody AST  
thisMode          → non-lexical-this  
env               → global LexicalEnvironment  
privateEnv        → null

Let internalSlotsList be:

  ```
  [[Environment]]

  ```

Это список внутренних слотов, которые будут созданы.

---

## 🔥 Шаг 2

`Let F` = `OrdinaryObjectCreate(functionPrototype, internalSlotsList)`

Вот здесь начинается реальное создание объекта.

## 3️⃣ OrdinaryObjectCreate — очень подробно

Алгоритм:

1. ` Let obj = MakeBasicObject(internalSlotsList)`  
2.  `Set obj.[[Prototype]] = functionPrototype`  
3.  `Return obj`

То есть:

- создаётся "пустой" объект
- ему назначается прототип
- возвращается

---

## 4️⃣ MakeBasicObject — максимально подробно

Это самый низкий уровень.

1. ` Create a new object O`  
2.  `For each slot in internalSlotsList:`  
     `Add slot to O with value uninitialized`  
3.  `Return O`

# 🧠 Почему каждая функция получает prototype?

Когда ты объявляешь:

function A() {}

Во время `OrdinaryFunctionCreate` для обычных функций вызывается:

MakeConstructor(F)

Этот алгоритм:

1. Создаёт новый объект:
    

proto = OrdinaryObjectCreate(%Object.prototype%)

2. Делает:
    

F.prototype = proto  
proto.constructor = F

Именно поэтому у функций есть `.prototype`.

---

⚠️ Важно:

- стрелочные функции не получают `.prototype`
    
- методы класса тоже не получают `.prototype`
    

Потому что `MakeConstructor` не вызывается.

# 2️⃣ Как bootstrap создаёт %Function%

Вот это самый сложный момент во всём JS.

Проблема:

> Чтобы создать функцию, нам уже нужна функция.

Парадокс.

---

## 🔥 Решение — bootstrap

Спецификация не расписывает низкоуровневую магию,  
но логика такая:

1. Движок создаёт базовый пустой объект
    
2. Ручным bootstrap-кодом добавляет внутренний метод [[Call]]
    
3. Назначает прототипы
    
4. Связывает всё в систему
    

---

## 🔬 Упрощённо bootstrap делает:

Шаг 1:

objectProto = MakeBasicObject()  
objectProto.[[Prototype]] = null

Шаг 2:

functionProto = MakeBasicObject()  
functionProto.[[Prototype]] = objectProto

Шаг 3:

FunctionConstructor = MakeBasicObject()  
FunctionConstructor.[[Call]] = builtin code  
FunctionConstructor.[[Prototype]] = functionProto

Шаг 4:

functionProto.constructor = FunctionConstructor

Шаг 5:

objectConstructor = MakeBasicObject()  
objectConstructor.[[Call]] = builtin Object constructor  
objectConstructor.[[Prototype]] = functionProto

---

## 🔥 Итоговая структура:

%Object.prototype% → null  
  
%Function.prototype% → %Object.prototype%  
  
%Function% → %Function.prototype%  
  
%Object% → %Function.prototype%

Это создаёт основу всей объектной модели JS.

---

# 3️⃣ Почему Function — это функция, создающая функции?

Потому что у него есть внутренний метод:

[[Call]]  
[[Construct]]

Когда ты пишешь:

new Function("a", "b", "return a + b")

Происходит:

Call(%Function%, arguments)

Внутри встроенный алгоритм:

1. Создать новый FunctionObject
    
2. Скомпилировать переданный sourceText
    
3. Вернуть функцию
    

---

То есть `Function` — это runtime-компилятор.

---

## 🔥 Важный момент

`Function` создаёт функции в текущем Realm.

Поэтому:

iframe.contentWindow.Function !== window.Function

---

# 🧠 Глубинная картина всей системы

После bootstrap у тебя есть:

Realm  
  ├── %Object%  
  ├── %Function%  
  ├── %Array%  
  └── ...  
  
%Object.prototype% → null  
%Function.prototype% → %Object.prototype%  
  
%Function% → %Function.prototype%  
%Object% → %Function.prototype%

И теперь любая функция, созданная позже:

function A() {}

Получает:

A.[[Prototype]] → %Function.prototype%  
A.prototype → новый объект  
A.prototype.[[Prototype]] → %Object.prototype%

---

# 💥 Самое важное осознание

JS не строится "сверху вниз".

Он строится через bootstrap-инициализацию:

1. Создать базовый объект
    
2. Создать Function
    
3. Связать их
    
4. Создать остальные встроенные объекты
    

---

# 🎯 Ключевой вывод

prototype появляется не потому что ты объявил функцию.

Он появляется потому что:

> OrdinaryFunctionCreate вызывает MakeConstructor

А MakeConstructor создаёт `.prototype` объект.
